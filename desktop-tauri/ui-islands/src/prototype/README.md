# 原型：固定上游 IP 模态框的三个布局变体

> ⚠️ **这是一次性代码，不要并入正式功能。** 它回答的是「弹窗内部的**信息层级
> 该怎么排**」，答案一旦落地，这个目录就该删掉。

## 它回答什么问题

固定上游 IP 的弹窗要同时容纳四件事：IP 组（主要输入）、等待响应超时、切换状态码、
总开关。这四样在同一个弹窗里怎么排，才能让用户一眼分清：

- 哪些是**必填**（开开关时至少一个 IP），哪些有**默认值**（状态码 502、超时 0 = 跟随全局）；
- **当前生效的值**是什么（组当前 IP 是谁、全局超时是 300 秒还是他改过）；
- 改完之后**会发生什么**（切 IP 与换账号是同时的）。

三种变体对这三件事给出不同的答案，所以结构不同，而不只是换个配色。

## 三个变体

| Key | 名字 | 结构特征 | 它押注的假设 |
|---|---|---|---|
| **A** | 分组卡片式 | 纵向三段，每段一张内嵌卡片；开关在**最后** | 用户是「一次配好、很少再改」，所以开关放在末尾读作「配好了再打开」 |
| **B** | 左右分栏 | 地址占左侧大头，规则挤在右侧窄栏；开关在**标题行** | 地址是主角、规则是附带，开关状态要一眼可见 |
| **C** | 清单＋轮换预览 | 地址是逐行条目（带序号、删除），右侧实时预览轮换顺序 | 用户会频繁增删地址，且关心轮换顺序（谁先谁后） |

## 怎么跑

依赖已装在 `ui-islands` 与 `ui-kit`（用仓库内缓存装的，不动全局 npm cache）：

```bash
cd desktop-tauri/ui-islands
npx vite build --config vite.prototype.config.ts
```

产物落到 `desktop-tauri/ui/prototype/`（**不入库**，见 `.gitignore`）。

然后启动一个网关实例，浏览器打开：

```
http://127.0.0.1:<端口>/?variant=A     # 或 B、C
```

底部浮动条点 ← → 切换，也可以按键盘左右方向键（输入框聚焦时不拦截）。

网关怎么起：与平时一样（`./target/debug/agent2api-server` + `AGENT2API_UI_DIR`
指向 `desktop-tauri/ui`）。原型读的是**真实的** `/api/pinned-upstream-ip`，
保存也真的落库 —— 所以三个变体除了布局之外行为完全一致，比较的才是设计本身。

## 关键点：它贴着真实界面

弹窗不是放在白纸上，而是挂在真实的账号页上（原型启动时会 `wbShowPage('accounts')`）。
这样密度、字号、间距都能和面板其它弹窗直接对照 —— 一个孤零零的路由会让所有变体
看起来都还行。

## 已知的粗糙处（原型不需要修）

- 保存成功后弹窗关闭并显示原始 JSON，没有做得更漂亮。
- 没有做「切换组当前 IP」那个按钮的交互（那是正式功能的一部分，不属于本原型的问题）。
- 拼错 IP 时只标红输入框 + 底部提示，没有逐行行内提示（C 变体有，其余两个没有 ——
  这本身就是三个变体的差异之一）。

## 这个原型已经暴露并修掉的问题

1. **弹窗必须包 `DialogContent`**：只用 `DialogHeader`/`DialogBody`/`DialogFooter`
   会绕过 Base UI 的 Portal 与 fixed 定位，弹窗被挤在文档流末尾、屏幕外看不见。
2. **桥接返回的是剥掉信封的 `data`**：按 `{success, data}` 的形状写类型会让
   `payload.pinnedUpstreamIp` 是 undefined，渲染直接白屏。
