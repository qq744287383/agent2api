# ADR-0001：固定上游 IP（WorkBuddy 国际版）

- 状态：已提议（待实现）
- 日期：2026-10-20

## 背景

`workbuddy-intl` 的全部上游请求都打 `https://www.workbuddy.ai`，该域名的 DNS 解析结果是动态的。用户希望把这组请求固定到一组自选 IP 上，并在链路变差时自动换 IP / 换账号。

调研确认了三件事，它们共同决定了本文的方案：

1. **只有 `www.workbuddy.ai` 需要覆盖。** `workbuddy-intl` 没有 growth / checkin 流量 —— `supports_growth` 只对国内版为真（`growth/mod.rs:811-817`），`copilot.tencent.com` / `www.codebuddy.cn` / `www.workbuddy.cn` / `static.workbuddy.cn` 对国际版结构性不可达。国际版的目录、余额、续期、保活、对话全在同一域名下。
2. **所有请求汇聚到 `egress::client_for`。** 对话与保活经 `upstream::request::send_chat_request`，目录 / 余额 / 续期经 `auth_http::send_raw`，两条最终都落到 `egress::client_for(Option<&ResolvedProxy>)`。
3. **「等待响应超时」发生在流式响应开始之前。** 它在 `upstream/request.rs:177` 生效，此时还没把 `ForwardOutcome::Stream` 交给客户端，**因此换号是可能的**。一旦流式开始就无法再换号，这使得「首帧之后」的超时无法用于切换 —— 这是本方案只用 `headers` 超时、不加「首个 SSE 事件」超时的根本原因。

## 决策

### 1. 用 `reqwest` 的 DNS 固定，而不是改 URL 或自建连接器

`ClientBuilder::resolve("www.workbuddy.ai", SocketAddr)` 把域名指向指定 IP，同时保留 URL 里的 Host 与 TLS SNI。这样 `Origin` / `Referer` / 证书校验全部不受影响。

- **否掉的方案**：把 base_url 换成 `https://<ip>` —— 会破坏 SNI 与证书校验，也会让上游按 Host 分流的行为失真；自建 connector —— 成本远高于一个 builder 调用，且要自己处理 TLS 与连接池。

### 2. 固定 IP 落在 client 层，并进入缓存键

`egress::client_for` 的客户端缓存目前只按 `代理 + connect_ms + read_backstop_ms` 做键（`egress.rs:121-137`）。固定 IP 必须进入这个键，否则不同 IP 的账号会共用同一个已解析的客户端。

- 否掉的方案：在 `TransportRequest` 上带 IP、让调用点各自处理 —— `send_raw` 有多个调用方（目录 / 余额 / 续期）且都拿不到 provider 身份，逐个改会漏。

### 3. 出网代理优先，冲突时记日志

`reqwest` 一旦配置代理，DNS 由代理完成，`.resolve()` 不再生效。两者同时存在时选**代理**（不改变存量账号的外网表现），并把「固定上游 IP 未生效」写进请求日志，而不是静默忽略。

- 否掉的方案：固定 IP 优先 —— 会静默改变配了代理的账号的出口，风险高于收益；保存时报错 —— 会让已配代理的存量账号无法保存。

### 4. 超时命中时跳过「同账号原地重发」

现状是一次「等待响应超时」会先在同一账号重发（默认 3 次），每次重新等满超时，之后才换人 —— 一次故障最坏会把客户端挂住 `4 × 300` 秒。单次超时已经是「这个 IP 不可用」的强信号，重发不引入新变量。

- 因此：超时 → 直接前进 IP + 换账号。
- 状态码命中 → 记录一次失败，切 IP + 换号，**继续重试**；在换号次数用尽时把最后一次上游错误返回客户端。

### 5. 唯一的终点是「换号次数」，IP 可以多圈

复用全局的 `retryCrossProviderCount`（默认 5），不新增配置。IP 列表轮完一圈后从头继续，账号照常前进，直到换号次数用尽或队列里没有账号。

- 否掉的方案：IP 一整圈失败就收尾 —— 用户早期提过，但后来又选择「IP 轮完从头再来」；后者与「换号次数是唯一预算」更一致，也避免「IP 少、账号多」时过早放弃。

### 6. 账号级 IP 被自动轮换时「直接改写」

账号策略的 IP 是用户手动选的，但自动切换会**写回**账号记录，而不是只在本次请求内临时前进。面板因此所见即所得。

- 代价：系统会改写用户的显式选择。这是有意为之 —— 临时值会让面板显示与实际不符，用户更难判断当前状态。

### 7. 换 IP 组即重置

改动 IP 列表（增删任意一项）时，组当前 IP 与所有账号的独立 IP 一并重置为「跟随组」，组当前 IP 从**新列表**里重新选一个。

- 理由：IP 被删掉后，任何指向它的绑定都是悬空引用。与其逐个判断哪些失效，不如整体重置 —— 用户刚改完列表，正是愿意复核的时刻。

## 影响

- 新增配置键一组（开关 / IP 列表 / 超时 / 状态码 / 组当前 IP），沿用 `config/types.rs` + `parse.rs` + `mod.rs` + `sql.rs` 的四段式。
- 账号新增一个可选字段（独立 IP）。账号记录本就是 JSON blob，**不需要 schema 迁移**。
- `egress::client_for` 增加带固定 IP 的变体，并改缓存键。
- 转发链在超时路径上新增一个动作，与既有的 429 / 401 / 普通错误三档并列。
- 面板：组菜单加一项、新建模态框、组标题后加 IP 与切换按钮、账号表加一列、i18n 六语与前端产物重建。

## 未决 / 后续

- 本 ADR 只覆盖 `workbuddy-intl`。若将来国内版也要，需要重新评估（它还有 growth 域，命中面不同）。
- 固定 IP 与「模型测试」等手工探测路径的关系未定 —— 那些路径不带账号身份。
